## [v0.1.0] - 2026-11-12

### Highlights

- A framework-neutral format for assessment records: evidence manifests, a scope of providers, shared platforms and products, control implementation records, and crosswalks
- Several separately marketed products on one shared platform: a platform control is recorded once and inherited by each product, and each product gets its own assessment
- Per-product, per-audience views and resolutions that withhold anything naming another product, with the reason, so public and NDA outputs cannot disclose the others
- `assessment` CLI and an OSCAL component definition export

### Added

- `evidence` package: the evidence manifest, its validation, set loading and SHA-256 verification ([`921b9fe`](https://github.com/opensecurity-dev/assessment-spec/commit/921b9fe))
- Evidence freshness per tool, by artifact age and vulnerability-database age, with ages written as duration strings ([`c1e3af4`](https://github.com/opensecurity-dev/assessment-spec/commit/c1e3af4))
- `mentions` distinguishes an artifact that names no system (`[]`) from one whose collector declared nothing (absent) ([`0c31c0a`](https://github.com/opensecurity-dev/assessment-spec/commit/0c31c0a))
- `audience` package: public, NDA and internal, ordered ([`0cf4655`](https://github.com/opensecurity-dev/assessment-spec/commit/0cf4655))
- `scope` package: organization, providers, shared platforms, systems and components, with validation ([`862ab06`](https://github.com/opensecurity-dev/assessment-spec/commit/862ab06))
- Per-system evidence views for each audience, withholding artifacts that name other systems or whose mentions are undeclared ([`f5b61f6`](https://github.com/opensecurity-dev/assessment-spec/commit/f5b61f6))
- System markers, mention detection in any text, and a check for artifacts naming systems their manifests omit ([`1d10a0b`](https://github.com/opensecurity-dev/assessment-spec/commit/1d10a0b))
- `controls` package: implementation records with status, origination, inheritance, prose, evidence, findings, attestations and visibility ([`2eecc0f`](https://github.com/opensecurity-dev/assessment-spec/commit/2eecc0f))
- Control resolution: a system's effective status for a baseline plus its added controls, with the contributing records, the weakest verification, and audience-filtered prose, evidence and findings ([`a6930c3`](https://github.com/opensecurity-dev/assessment-spec/commit/a6930c3))
- `controls.LoadBaseline` for baseline files ([`d669a70`](https://github.com/opensecurity-dev/assessment-spec/commit/d669a70))
- `crosswalk` package: criterion identifiers mapped to control IDs with source and licence, and a system's coverage of a framework ([`dcc663f`](https://github.com/opensecurity-dev/assessment-spec/commit/dcc663f))
- `schema` package: generated, embedded schemas for the evidence manifest, scope, controls and crosswalk ([`3d24969`](https://github.com/opensecurity-dev/assessment-spec/commit/3d24969))
- `assessment` CLI with `validate`, `freshness`, `view`, `resolve` and `coverage` ([`cb988d4`](https://github.com/opensecurity-dev/assessment-spec/commit/cb988d4))
- `oscal` module: an OSCAL 1.2.3 component definition per system and audience, with stable UUIDs and effective status for inherited and hybrid records ([`23084bb`](https://github.com/opensecurity-dev/assessment-spec/commit/23084bb))
