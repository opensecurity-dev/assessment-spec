# Release Notes - v0.1.0

**Release date:** 2026-11-13

## Overview

First release of `assessment-spec`: a framework-neutral format for the
records a security assessment is built from, a Go library that validates and
resolves them, the `assessment` CLI, and an OSCAL export.

Collectors write evidence manifests beside what their tools produce. An
organization describes its providers, shared platforms and products once,
and records each control on the scope that implements it. Engines then get,
for each product and audience, the evidence and control status they may
publish, and can map it to any framework through a crosswalk.

## Highlights

- **Several products, one platform.** A platform control is recorded once and
  inherited by every product on it. Each product is assessed on its own.
- **Nothing leaks between products.** Views and resolutions for public and
  NDA audiences withhold artifacts and prose that name another product, and
  say what was withheld and why. Markers catch artifacts whose collectors
  forgot to declare a product they name.
- **Honest status.** A control nothing records is `unassessed`, never
  `implemented`; combined sources take the weakest status; every resolved
  control carries the weakest verification behind it.
- **Fresh evidence.** A scan run with an out-of-date vulnerability database
  is stale even when the scan itself is new.
- **Frameworks by identifier.** Crosswalks map criterion IDs to controls and
  carry no criterion text. OSCAL is an export, in a separate module.

## Installation

```bash
go install github.com/opensecurity-dev/assessment-spec/cmd/assessment@v0.1.0
```

As a library:

```bash
go get github.com/opensecurity-dev/assessment-spec@v0.1.0
go get github.com/opensecurity-dev/assessment-spec/oscal@v0.1.0   # OSCAL export
```

Go 1.26 or later is required.

## Added

- `evidence`: the evidence manifest, validation, set loading, SHA-256
  verification and per-tool freshness.
- `audience`: public, NDA and internal.
- `scope`: the scope document, its validation, per-system views for each
  audience, markers and mention detection.
- `controls`: implementation records, validation, baselines and resolution.
- `crosswalk`: crosswalk files and framework coverage.
- `schema`: generated, embedded JSON Schemas for every document.
- `assessment` CLI: `validate`, `freshness`, `view`, `resolve`, `coverage`.
- `oscal` module: OSCAL 1.2.3 component definitions per system and audience.

## Not yet included

- OSCAL assessment results and POA&M.
- Crosswalks for real frameworks; supply your own, recording their source
  and licence.
